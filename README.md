# 看图 — NAS 照片筛选工具

在手机/平板浏览器里一张一张看 NAS 上的照片，喜欢的上滑一下就存下来。
看图器用的是 PhotoSwipe，和 Documents 里那个一样丝滑：左右滑切换、
双指缩放、前后预加载。

## 功能

- 按文件夹浏览：子目录显示为方块缩略图（封面是文件夹里按名字排的第一张
  照片），和照片网格一个样式，点进去看，顶部面包屑返回；列表页
  右滑回上级目录（内容跟手右移、左边缘显现“‹ 上级目录”，松手后旧列表从手指
  停下的位置直接飞出去、新列表从左侧滑进来，两段动画连着，不断档；
  幽灵层按滚动恢复后的位置对齐，接缝处新旧两层上下不错开；
  上级目录拉过一次就记下来，回来立刻渲染，不会卡；
  回来时滚动位置恢复到离开时的地方，不回顶部）；
  目录页：每个文件夹方块底部有一条细进度条（已看过的占比，不显示数字），
  没看完是黄色、看完了变绿色，全部看完的文件夹和单张一样变灰；
  文件夹排序：没看完的排前面，按更改日期倒序（新改过的在前）；
  看完的排后面，按文件夹名正序；
  看图时滑得快一次越过好几张，中间路过的也都记成已看过（之前只记落脚那一张）；
  在最顶上向下拉刷新列表（指示条文字贴在条的底部，灵动岛挡不住）
- 网格浏览（缩略图懒加载），点一张进全屏看图；网格里不显示文件名；
  状态只用颜色表示，不加字：看过的图片变灰、保存过的描绿边；
  启动时先显示“加载中…”，列表拉回来才显示筛选行和张数（之前启动
  会看到一排筛选按钮，下面一片黑，看着像坏了）
- **看图时上滑保存**：图片不动，只有中央金色 ✓ 随拉动慢慢显现，松手存下后
  ✓ 弹一下、底部圆点立刻出现；存到目标目录下按年的子目录（今年是 2026 就存到
  `2026/` 里），重名自动加 -1、-2；下滑关闭看图器（图片跟手下移，
  松手即关）；左右滑是前后，看到最后一张就停，不循环回开头；
  双指放大看细节时不会误触发保存；左右滑时列表页不会从背后透出来
- 看图器底部只有一条进度条（看到第几张）和一个金色圆点（这张存过才显示）
- 看过的照片自动记下来：网格里变暗，下次打开自动滚动到上次
  看到的那张
- 筛选：全部 / 未看过 / 已看过 / 已保存；没照片的目录不显示筛选行和张数行
- **收藏夹视图（v1.15）**：顶栏分段切换 `照片库 | 收藏夹`，收藏夹读目标
  目录、按年文件夹显示，网格、进度条、排序、看图器和照片库完全一样；
  收藏夹里上滑和回车都不重复保存，只弹一下 ✓、报“已在收藏夹”；
  已保存的绿边和金色圆点在收藏夹里不重复画；已看按视图分开记；
  收藏夹一张都没有时显示“收藏夹还是空的，去照片库上滑保存一张吧”；
  不提供删除和取消收藏
- 群晖的 @eaDir 系统目录不显示、不计入张数
- 保存是服务端复制，不经过手机，快且不耗流量；已保存、已看记录存在
  `./data/state.json`，重启、升级都在
- 键盘：回车保存当前这张（iPad 外接键盘）；收藏夹视图里回车只提示“已在收藏夹”，不重复保存

## 全屏

iPhone 的 Safari 里开网页不能全屏，这是 Safari 的限制，不是这个工具的
问题。办法：点分享 → 添加到主屏幕，再从主屏幕打开就是全屏了（没有
Safari 的地址栏和工具栏）。页面顶部会提示一次，关掉就不再出现。

## 部署（群晖 Docker）

1. 把这个文件夹拷到群晖上，例如 `/volume1/docker/photo-culler`
2. `cp .env.example .env`，按你的实际路径改里面两行：
   - `PHOTOS_DIR`：要看的照片目录
   - `DEST_DIR`：喜欢的照片保存到哪里
3. `docker compose up -d --build`
4. 同一 WiFi 下手机浏览器打开 `http://群晖IP:8090`

**从 v1.16 及更早版本升级到 v1.17**：`.env` 里按需加上 `YANDERE_*` 那几行
（不加就按默认 6 小时跑）；**部署后停掉群晖上原来跑 `i.php` 的定时任务**，
新旧两个抓图器不能同时跑。照片目录挂载 v1.17 起不再只读（抓图器要往里写
新图），`docker-compose.yml` 已经改好了，`up -d` 会自己处理。

端口 8090 被占了就改 `docker-compose.yml` 里的 `"8090:8080"` 前面那个数字。

## 为什么滑起来快

丝滑靠的不是原生还是网页，而是三件事，这个工具三件都有：

- **看预览图，不看原图**：查看器里显示的是服务端现做的 2000px 预览图
  （一张 24MB 的原图，预览约 1MB，实测），不是 10–20MB 原图；双指缩放
  就在预览图上做。
- **预加载**：看第 N 张时，前后几张已经在后台加载了。
- **缓存 + 预热**：缩略图和预览图只生成一次，存在 `./data/.thumbs`，文件
  没变就一直用缓存；容器启动后自动在后台预热全库。
- **孤儿缩略图清理（v1.16）**：NAS 上删了文件夹/照片、改了名、改了文件，
  它在 `./data/.thumbs` 里的缩略图和预览图就没用了。服务端启动后清一次，
  之后每 24 小时清一次（后台跑，不挡页面）；想立刻清就调
  `POST /api/clean-thumbs`，返回删了几个、留了几个、释放了多少字节。
  清理按白名单删：只删不在现存照片之列的 `*.jpg`，活图的缓存和别的文件
  不动；`dims.json` 里对不上的旧宽高条目顺手一起清掉。
- **yandere 抓图（v1.17）**：原来群晖上每 12 小时跑一次的 PHP 脚本 `i.php`
  并进来了，用 Python 标准库重写（`app/yandere.py`），不用再跑 PHP。
  每 6 小时一轮（`.env` 里 `YANDERE_INTERVAL_HOURS` 可改）：拉今天、昨天
  的每日榜单 + 最近热门，往前 2–4 天只在对应日期文件夹不存在或为空时回填；
  图按 `<id>.jpg` 存到照片目录下的东京日期文件夹里。列表之间停 2 秒、
  图片之间停 1.5 秒（各加 0–1 秒随机抖动），429 读 `Retry-After` 退避，
  单张失败不杀整轮；下载先写 `.tmp`、校验是 JPEG 才原子改名；状态存在
  `./data/yandere.json`。`GET /api/yandere/status` 看上次/下次运行和统计，
  `POST /api/yandere/run` 手动立刻跑一轮。抓完自动给新文件夹预热缩略图。
  顶栏点「状态」就能在页面上看：版本、抓图开关、间隔、已抓张数、上次/下次
  运行时间、本轮统计和最近错误，每 30 秒自动刷新；「立即抓图」就是手动跑一轮。

在家里 WiFi 下，缓存好的预览图几毫秒就到，和 Documents 本地看图的感觉
接近。原生 App 同样要先下载原图再显示，快也是因为它在后台做了同样的
预览和预加载。

## 注意

- 只在家庭局域网用，不要直接暴露到公网。想在外面看，走你现成的群晖反代
  加登录保护，和 yuvomi 一个办法。
- HEIC 照片：iPhone/iPad 的浏览器能直接看原图；Docker 里装了 pillow-heif，
  缩略图和预览图也能做。JPG/PNG 不受影响。
- 只读挂载源目录，工具本身不会改你的原图；保存是复制，不是移动。
  （v1.17 起照片目录不再只读挂载：yandere 抓图器只写新文件，永不删除、
  永不覆盖已有文件。）

## 排障：页面一片空白怎么办

先看页面顶部有没有黄色警告条，它会直接告诉你原因。最常见的是：

1. **照片目录指错了**：新目录下没有 `.env`（压缩包里只有 `.env.example`），
   或 `.env` 里的 `PHOTOS_DIR` 路径不对。compose 现在没填会直接报错停下，
   不会静悄悄挂一个空目录。`docker compose logs` 里也会有 WARNING。
2. **浏览器缓存了旧文件**：页面和脚本现在是不缓存的，但之前缓存过的旧版
   可能还留着。用无痕浏览打开一次，或在设置 → Safari → 清除历史记录与
   网站数据后重试。脚本 4 秒没加载成功时页面顶部会出红色报错条。
3. **容器没起来**：`docker compose ps` 看一眼，再看 `docker compose logs`。
